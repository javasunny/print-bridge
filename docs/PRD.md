# Print Bridge 当前设计

本文以 0.1.7 的代码为准，描述已经实现的行为与明确限制。原始规划中尚未实现的登录启动、跨连接幂等识别、多队列并行、解析进程隔离和待核查归档，不作为当前功能承诺。

## 1. 目标与平台

Print Bridge 在 Windows 当前用户会话中运行，把已安装驱动且能够本机打印的 Windows 队列通过 IPP 提供给 Apple 设备。发布目标是 Windows 11 x64；其他 Windows 版本与 ARM64 尚未验收。macOS 只支持 `--simulate` 开发模式。

程序不作为 Windows Service 运行。关闭窗口继续托盘运行；主动退出、用户注销或电脑休眠时无法正常接收打印。不提供登录启动或云端打印。

## 2. 入口与总体架构

Tauri 静态界面通过本地命令管理 Rust 核心，管理功能不通过局域网开放。局域网只提供 IPP 与队列专属 PPD 下载，没有网页上传或通用文件上传 API。

```text
Apple 系统打印界面
  → HTTP / IPP 服务（src/service.rs、src/ipp.rs）
  → 文档校验与转换（src/document.rs）
  → SQLite + PDF 存储与调度（src/store.rs）
  → SumatraPDF 独立进程（src/printing.rs）
  → 指定 Windows 驱动与打印队列

Tauri 管理命令（desktop/src/app.rs）→ Rust 核心
Bonjour 发布（src/discovery.rs）→ Apple 设备发现每个启用队列
```

## 3. 打印机配置

每台共享打印机保存桥接 ID、显示名称、Windows 队列名称、启用状态、最大份数、支持纸张、默认纸张与双面能力。

- 桥接 ID 仅允许字母、数字、横线和下划线，最长 64 字节。
- 纸张支持 A3、A4、A5、A6、Letter、Legal、Tabloid；选择须非空、无重复且包含默认纸张。
- 份数上限为 1–99；双面启用后允许长边或短边翻转。
- 只枚举队列及驱动基本信息，纸张和双面由用户手动配置，不自动推断或验证实体能力。
- 不同桥接 ID 不能绑定同一 Windows 队列。仍有未完成或待核查任务时不能更换原队列绑定。

禁用打印机后停止接受及领取该队列任务；重新启用后恢复等待任务。执行前能力已不匹配的任务失败，不修改原任务选项，也不改投默认打印机。

## 4. 监听与发现

桌面启动时直接填入 `0.0.0.0:8631`（全部 IPv4 网卡），不等待 IP 检测；可手动修改。已保存的共享队列独立于系统队列枚举加载。服务只在用户点击启动后监听；Mac 手动添加时使用 Windows 的实际局域网 IP。

每台启用打印机提供 `/ipp/printers/{id}`，并发布 `_ipp._tcp.local.` 与 AirPrint `_universal._sub._ipp._tcp.local.`。TXT 反映队列、端口、认证、格式和已配置能力。回环监听不发布局域网打印机。

运行期间每 60 秒重新公告全部共享队列；停用队列或停止服务会结束旧刷新线程并撤销广播，修改配置会更新广播。发现失败会显示错误，但不阻断手动 IPP 打印。应用不自动修改 Windows 防火墙，需在私有局域网放行服务 TCP 端口和 UDP 5353，排障见 [AirPrint 说明](airprint.md)。

## 5. 设备认证

默认开启 HTTP Basic 认证：用户名为设备 ID，密码为随机 256 位令牌。令牌只展示一次，数据库仅保存 SHA-256 哈希。撤销设备会删除凭据，已接受的任务保留。

打印机能力查询和专属 PPD 下载允许匿名访问；提交、任务查询与取消在认证开启时要求有效凭据，任务查询和取消按设备及打印机隔离。

认证可在设置中关闭；运行中修改在重启服务后生效。免认证请求共用 `anonymous` 身份和相应任务配额，客户端之间不具有设备身份隔离。文档持久化前再次核对服务状态、设备撤销与队列能力。

当前没有 TLS / IPPS，Basic 凭据和打印文档没有传输加密，仅用于可信局域网。

## 6. IPP 协议与路由

支持 IPP 1.1 / 2.0，已实现：

| 操作 | 行为 |
|---|---|
| Get-Printer-Attributes | 查询当前队列能力、状态及认证策略 |
| Validate-Job | 校验当前参数，不接收文档、不预留容量 |
| Print-Job | 接收单个支持格式的文档，校验并持久化后排队 |
| Create-Job | 创建等待文档的任务 |
| Send-Document | 为所属队列与设备的等待任务上传单个文档；结束上传后排队 |
| Get-Job-Attributes / Get-Jobs | 查询当前设备在当前打印机的任务 |
| Cancel-Job | 取消尚未开始打印的任务 |

任务 URI 为 `/ipp/printers/{id}/jobs/{job}`；PPD 地址为 `/ipp/printers/{id}/driver.ppd`。未支持的操作、格式及影响输出的显式选项被拒绝。兼容的 Apple 私有作业票据作为客户端元数据，不绕过标准输出参数验证。

## 7. 文档与打印选项

支持 PDF、JPEG、300 dpi 的 8 位灰度与 24 位 sRGB URF / PWG Raster。非 PDF 文档先转换为 PDF，再进入相同存储与打印流程。不支持多文档任务、PostScript 和未声明的栅格编码。

PDF 校验结构、加密、页面和大小；最多 100 MiB、1–500 页。输入与转换结果均受大小限制；栅格单页解码最多 98 MiB、全任务累计最多 512 MiB，渐进式 JPEG 最多 8M 像素。PDF 解析没有独立进程超时与内存隔离。

打印参数包含纸张、份数、单双面及 `auto / color / monochrome`。显式彩色或黑白传给驱动，`auto` 沿用驱动默认值；桌面没有颜色控件。纸张通过 Windows 标准 paperkind 编号传递，按可打印区域保持比例适应缩放。页码范围应由客户端生成相应文档；不支持纸盒和装订等选项。

## 8. 持久化与调度

SQLite 使用 WAL、FULL 同步与应用数据目录的实例文件锁。文档使用服务端生成的随机文件名，文件写入并同步、数据库事务提交后才返回接受成功。启动时清理孤立文件；缺失文件的等待任务转为失败。

当前只有一个后台工作线程，**所有打印机全局串行**。领取任务时在数据库锁内条件更新为 `processing`，再释放锁调用打印程序。取消与领取使用相同的状态条件，取消成功后不会启动打印调用。

没有可靠的跨连接业务幂等键，也没有按内容摘要去重。相同文件的主动重复提交被视为独立任务；客户端网络重试也可能创建重复任务。保存的文档摘要不构成重试识别机制。

## 9. 状态与恢复

| 内部状态 | 含义与处理 |
|---|---|
| `pending-document` | 等待上传文档，可取消 |
| `pending-final-document` | 已收到文档但等待结束上传，可取消 |
| `pending` | 已持久化并等待调度，可取消 |
| `processing` | 已领取，正在调用打印程序，不能按执行前语义取消 |
| `submitted` | 程序报告已转交 Windows，不代表确认出纸 |
| `failed` | 输入/目标校验失败、启动失败或等待文档超时等 |
| `uncertain` | 调用超时、非零退出或恢复时原状态为处理中；不自动重打 |
| `canceled` | 执行前取消 |
| `simulated` | 模拟完成，没有真实打印 |
| `completed` | 空文档结束的 IPP 任务，没有真实打印 |

重启后 `processing` 转为 `uncertain`；等待任务重新核对文件和能力后可恢复。Windows 队列任务消失不证明已经出纸。待核查材料保留，目前只提示人工核查，没有人工归档或重打功能。

停止服务会停止接受和领取任务，保留等待任务。主动退出时若仍有打印调用则拒绝立即退出并提示等待；关闭窗口仅隐藏到托盘。

## 10. SumatraPDF 集成

SumatraPDF 不随安装包或仓库分发。用户在设置中手动下载，应用从官方 HTTPS 域获取 x64 portable ZIP、限制下载大小并安装到用户应用数据目录。

3.6.1 使用锁定 ZIP / EXE SHA-256；后续稳定版在 Windows 验证有效 Authenticode 签名、预期发布者与产品版本，再保存本地摘要用于离线校验。检查更新不会自动安装；服务停止且当前调用结束后才能下载或更新。失败保留旧组件。

使用参数数组调用指定队列，文档不作为 RAW 数据发送给 GDI 打印机。打印调用超时为 300 秒；超时、非零退出和状态不可确认都进入待核查，不自动重试。详细第三方说明见 [SumatraPDF 声明](../third_party/SumatraPDF-NOTICE.txt)。

## 11. 资源限制

| 项目 | 当前实现 |
|---|---|
| 输入 / 转换后的 PDF | 各最多 100 MiB，PDF 最多 500 页 |
| 未完成或待核查任务 | 每设备最多 20 个、每打印机最多 100 个 |
| 文档磁盘配额 | 2 GiB；接收时要求写入后至少预留 1 GiB 可用空间 |
| IPP 并发处理 | 共享 4 个接收/处理许可，超出返回繁忙 |
| 已认证或免认证请求体读取 | 总计最多 300 秒；没有单独的空闲超时 |
| 无凭据能力请求体读取 | 最多 10 秒，并限制请求体大小 |
| Create-Job 等待文档/结束上传 | 120 秒，过期转失败 |
| 打印调用 | 全局 1 个，最多 300 秒，超时进入待核查 |

这些是代码中的固定值，目前没有对应设置界面。超时用于资源控制，不能据此认定是否已经打印。

## 12. 记录、清理与数据目录

- 任务界面读取最近 1000 条任务，并按当前打印机筛选；元数据不按天自动删除。
- “清除记录”删除所有打印机的 `submitted / simulated / failed / canceled / completed` 记录及对应文档，保留等待、处理中和待核查任务，不受当前筛选影响。
- 已结束 PDF 超过 24 小时后清理；等待、处理中和待核查文档不自动删除。
- 连接诊断在内存中保留最近 100 条请求，记录来源 IP、时间、路由、操作及结果，不记录凭据、请求头、文档标题或内容。可以清空，后续请求继续记录。
- 数据位于 Tauri 用户应用数据目录的 `production` / `simulation` 子目录；组件位于同一根目录的 `tools/sumatra`。两种模式数据与实例锁隔离。

## 13. 验证与兼容性

常规 Rust 与前端测试覆盖协议、认证、文档转换、状态流转、取消竞争、恢复和记录清除，不执行真实打印。系统队列创建、原生 Bonjour 和官方下载测试默认忽略，需要明确选择。

已有 macOS 到 Windows 首次真实打印及防火墙修复后自动发现恢复的用户反馈；完整设备组合、iPhone/iPad、认证、多队列和实际纸张/双面效果仍需验收。不宣称已获 AirPrint 或 IPP Everywhere 认证，详见 [Windows 验证记录](windows-validation.md)。

## 14. 发布与非目标

公开仓库提供源代码，GitHub Release 提供 Windows x64 NSIS 安装包、独立 EXE、许可证和 SHA-256 校验文件。项目自身使用 MIT；依赖保留各自的许可证与源码入口。构建与发布步骤见 [发布指南](RELEASING.md)。

当前不提供：公网打印、IPPS、网页管理、驱动安装、Windows Service、登录启动、应用自动升级、代码签名安装包、多队列并行、可靠重试去重、待核查人工归档及 PDF 独立进程隔离。这些是已知边界，不作为本次开源发布新增功能。
