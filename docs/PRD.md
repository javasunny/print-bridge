# Windows 多打印机 IPP 桥接工具开发文档

> 本项目从零开发，使用 Tauri + Rust，仅提供 IPP 打印入口，不提供网页上传或 HTTP 文件上传 API。
>
> 文档日期：2026-10-25。第 1–13 节保留原始需求，第 14 节为评审补充建议；其中候选方案和数值须在技术验证后定稿，不代表已完成验证。
>
> 2026-10-26 修订：按用户要求，将 SumatraPDF 随包分发改为在设置中手动下载、校验后使用；构建与测试不再依赖 Python。
>
> 2026-10-26 修订：按用户要求增加可关闭的设备认证，用于先验证打印流程。默认仍开启认证；关闭期间局域网客户端可直接打印，匿名任务共用身份。

## 1. 项目目标

开发一个运行在 Windows 上的多打印机桥接客户端。

用户在 Windows 客户端中选择需要共享的打印机。客户端通过 IPP 将这些打印机提供给 macOS，用户添加后，可在应用的系统打印对话框中选择目标打印机。

客户端在设置中提供 SumatraPDF 手动下载按钮，将收到的 PDF 通过对应 Windows 驱动提交打印，不要求用户自行查找安装程序或配置路径。

## 2. 功能范围

| 项目 | 要求 |
|---|---|
| 技术架构 | Tauri 桌面应用，Rust 实现全部后端逻辑 |
| Windows 打印机 | 枚举已安装打印机，允许共享多台 |
| macOS 接入 | 每台共享打印机提供独立 IPP 地址 |
| 打印入口 | 仅 IPP，不提供网页上传 |
| 文档格式 | 首版仅接受 PDF |
| 打印选项 | A4、份数、单面、长边双面、短边双面 |
| 打印执行 | 设置中手动下载并校验 SumatraPDF，调用目标 Windows 驱动 |
| 访问控制 | 设备令牌鉴权 |
| 任务管理 | 持久化、排队、状态查询、排队任务取消 |
| 桌面功能 | 配置窗口、系统托盘、可选登录启动 |

双面选项根据每台打印机的能力开放。Windows 电脑需提前安装目标打印机驱动，并确保能够本机打印。

首版不包含：

- 网页打印、文件上传 API、远程管理页面。
- macOS 原生客户端。
- Bonjour/mDNS 自动发现。
- 非 PDF 格式的转换。
- 云服务、公网打印。
- 驱动自动安装。
- 彩色、其他纸张、纸盒及装订等扩展选项。

IPP 本身使用 HTTP 传输；“仅提供 IPP”指不额外提供网页或通用文件上传服务。

## 3. 总体架构

```text
macOS 应用
    │ 系统打印对话框选择打印机
    ▼
macOS 打印系统
    │ IPP：PDF、打印选项、设备凭据
    ▼
Windows Tauri 客户端
├─ 本地桌面界面
│  ├─ 共享打印机配置
│  ├─ 设备令牌管理
│  ├─ 任务列表
│  └─ 服务与启动设置
│
├─ Rust 后端
│  ├─ IPP 服务与鉴权
│  ├─ PDF 校验
│  ├─ SQLite 与文件存储
│  ├─ 每台打印机的任务队列
│  └─ Windows 打印机适配层
│
└─ 用户在设置中下载的 SumatraPDF
         ▼
   Windows 驱动与打印队列
         ▼
       目标打印机
```

本地界面通过 Tauri 命令访问 Rust 后端。管理功能不通过局域网开放。

## 4. Windows 客户端

### 4.1 打印机配置

列出当前 Windows 用户可访问的已安装打印机，允许勾选多台进行桥接。

每台共享打印机保存：

| 字段 | 用途 |
|---|---|
| 桥接 ID | 稳定标识，用于 IPP 路由与任务关联 |
| 显示名称 | 提供给用户识别的名称 |
| Windows 队列名称 | 实际打印目标 |
| 启用状态 | 是否接受新任务 |
| 能力配置 | 支持的纸张、单双面及份数限制 |
| 默认选项 | 请求未指定时采用的允许值 |

显示名称变更不改变桥接 ID 或 IPP 地址。

目标队列失效时，任务不能自动改投其他打印机。更换绑定前，应处理原绑定的未完成任务。

能力优先从 Windows 驱动获取；无法可靠获取时，允许本地手动配置。未经验证的能力不得直接对外宣称支持。

### 4.2 服务管理

提供以下操作：

- 启动、停止 IPP 服务。
- 设置监听地址和端口。
- 展示每台打印机的 IPP 地址及 macOS 添加说明。
- 查看服务状态和可安全展示的错误信息。
- 关闭窗口缩到托盘。
- 可选的当前用户登录启动。

停止服务时先停止接收新任务，再协调正在执行的任务。不得直接终止打印进程后认定任务未提交。

### 4.3 设备与任务管理

- 创建设备令牌，完整令牌仅在创建时展示。
- 查看设备名称、令牌标识并撤销访问权限。
- 按打印机筛选任务。
- 查看等待、处理中、已提交、失败、待核查和已取消状态。
- 取消尚未开始执行的任务。
- 对待核查任务提示检查 Windows 队列及实际出纸情况。

首版设备令牌允许访问已启用的共享打印机，不引入逐打印机权限配置。

## 5. macOS 接入

每台共享打印机提供独立地址，例如：

```text
ipp://<Windows地址>:<端口>/ipp/printers/office
ipp://<Windows地址>:<端口>/ipp/printers/front
ipp://<Windows地址>:<端口>/ipp/printers/warehouse
```

用户在 macOS“打印机与扫描仪”中分别添加需要的打印机。添加后，可在 ⌘P 打印对话框中选择目标设备。

首次使用时提供设备凭据；令牌不得放在打印机 URL 中。

实施时必须验证：

- macOS 能够向服务提交 PDF。
- 打印机名称及能力展示正确。
- 认证提示、凭据保存和令牌撤销行为正确。
- 多台打印机分别路由到对应 Windows 队列。
- 必要时提供匹配能力的 PPD 和添加说明。

不能仅凭 IPP 能力响应就认定 macOS 一定发送 PDF，也不将本项目宣称为完整 AirPrint 或 IPP Everywhere 实现。

## 6. IPP 服务

### 6.1 首版操作

计划支持：

| 操作 | 用途 |
|---|---|
| Get-Printer-Attributes | 查询打印机能力及状态 |
| Validate-Job | 校验格式和打印选项 |
| Print-Job | 提交单个 PDF 打印任务 |
| Get-Job-Attributes | 查询任务状态 |
| Get-Jobs | 查询当前设备的任务 |
| Cancel-Job | 取消尚未执行的任务 |

首版不支持多文档任务、Create-Job/Send-Document，以及 PostScript、PWG Raster 等非 PDF 输入。

### 6.2 请求处理

每次提交按以下顺序处理：

1. 解析并限制请求大小。
2. 验证设备凭据。
3. 查找目标打印机，确认已启用。
4. 校验文档格式及打印选项。
5. 检查重复请求。
6. 保存文件与任务记录。
7. 加入对应打印机队列。
8. 返回任务标识与状态。

请求不受支持的格式或选项时，返回明确的 IPP 错误，不静默改成其他打印效果。

### 6.3 鉴权与状态

任务提交、查询和取消必须鉴权，并限制设备只能查询、取消自己的任务。能力查询可按 macOS 互操作需要提供有限信息。

内部状态映射到 IPP 状态时，应保留“已转交 Windows 队列”和“实际出纸”的区别。不能通过状态命名让客户端误以为已经确认打印完成。

## 7. Rust 后端模块

| 模块 | 职责 |
|---|---|
| 配置 | 全局设置、共享打印机映射、能力配置 |
| Windows 适配 | 枚举打印机、读取能力、按需查询系统队列 |
| IPP | 编解码、请求处理、能力与状态响应 |
| 鉴权 | 令牌生成、哈希存储、撤销和访问检查 |
| PDF 校验 | 大小、结构、加密及页面检查 |
| 存储 | SQLite、文件管理和任务状态持久化 |
| 调度 | 每台打印机排队、恢复、取消和停止 |
| 打印执行 | 调用 SumatraPDF，处理退出与超时 |
| 清理 | 清理超过保留期的终态 PDF |
| 桌面控制 | 为 Tauri 界面提供受限管理命令 |

Windows 专用代码与通用逻辑隔离，使协议、鉴权和调度测试可以在 macOS 上执行。

具体依赖在实施时选定并锁定版本，不为尚未需要的功能引入组件。

## 8. 任务与队列

### 8.1 调度规则

- 同一打印机串行执行。
- 不同打印机允许并行，具体并发需验证 SumatraPDF 行为。
- 提交时固定目标打印机及其 Windows 队列绑定。
- 修改默认打印机不影响已排队任务。
- 目标失效不得自动改投。
- 无法确认是否提交的任务不得自动重试。

任务记录至少包括任务 ID、设备、目标打印机、打印选项、文件摘要、内部路径、幂等信息、状态和时间戳。

### 8.2 状态定义

| 状态 | 含义 |
|---|---|
| 等待 | 已保存，尚未开始打印调用 |
| 处理中 | 正在调用打印程序 |
| 已提交 | 打印程序报告成功转交，不代表实际出纸 |
| 失败 | 能确认未成功启动或明确未提交 |
| 待核查 | 无法排除已部分或全部提交 |
| 已取消 | 执行前已取消 |
| 模拟完成 | 仅用于开发验证，没有真实打印 |

服务重启后，原“处理中”任务转为“待核查”；等待任务校验目标后恢复。

Windows 队列任务消失不能单独证明成功出纸。

### 8.3 防重复提交

IPP 重复请求识别应包含设备、目标打印机、请求标识及文档和选项摘要。

- 能确认是同一请求的重试时，返回原任务。
- 相同重复请求标识对应不同内容时，拒绝提交。
- 明确记录识别窗口及限制。
- 新请求标识或窗口外提交，可能被视为新任务。

不能承诺识别所有由客户端重新创建的打印任务，也不能将主动再次打印与网络重试混为一谈。

## 9. SumatraPDF 集成

将固定版本的 SumatraPDF 作为独立程序，由用户在设置中点击下载，校验后由 Rust 后台调用。安装包不包含该第三方可执行程序。

要求：

- 固定版本及架构，校验下载摘要。
- 从固定的上游官方 HTTPS 地址下载，限制下载大小并核对归档及 EXE 摘要。
- 仅提取指定文件，校验通过后原子安装至用户应用数据目录。
- 显示下载状态和结果；失败可重试，不破坏已有可用文件，不自动下载。
- 通过应用数据目录中的固定路径定位，不依赖系统 PATH。
- 用户无需单独安装或配置路径。
- 使用参数数组启动，不经 shell 拼接。
- 对份数、纸张、单双面等参数进行允许值校验。
- 根据固定版本的退出行为判断结果。
- 处理超时及退出不明情况，避免自动重复打印。
- 保留上游项目、许可证及源码入口；若未来恢复随包分发，应重新落实对应源码与许可证材料。
- 第三方可执行程序不提交到源码仓库，也不参与应用构建。

打印链路为：

```text
PDF → SumatraPDF 渲染 → Windows 驱动 → 打印机
```

不把 PDF 字节作为 RAW 数据直接发送给 GDI 打印机。

## 10. 安全与存储

- 服务仅用于可信局域网。
- 首版使用设备令牌作为 IPP 认证凭据。
- 令牌只存哈希，不写入 URL、日志或错误消息。
- 普通 HTTP 上的认证不提供传输加密，部署说明必须说明此限制。
- 本地管理只通过 Tauri 命令开放。
- 校验 PDF 内容，不仅检查扩展名或 MIME 类型。
- 拒绝损坏、加密、无页面或超过限制的 PDF。
- 使用服务端生成的文件路径。
- 应用数据保存于用户应用数据目录。
- 更新程序不覆盖配置、令牌与任务记录。
- 仅清理超过保留期的终态 PDF。
- 模拟与真实打印使用隔离的数据目录。
- 不在日志中记录文档内容或敏感凭据。

## 11. 开发阶段

| 阶段 | 工作内容 | 完成条件 |
|---|---|---|
| 1. 工程基础 | Tauri/Rust、配置、SQLite、模拟适配 | 应用可启动，通用逻辑可测试 |
| 2. 打印机与本机打印 | 枚举、共享映射、设置中下载 SumatraPDF | Windows 下载并校验组件后可向指定目标提交测试 PDF |
| 3. 任务系统 | 多队列、持久化、取消、恢复、防重复 | 不串机，异常进入待核查 |
| 4. IPP | 协议、能力、鉴权、提交与查询 | macOS 可添加多个队列并正确打印 |
| 5. 桌面管理 | 打印机配置、令牌、任务列表、托盘 | 全部管理操作可在客户端完成 |
| 6. 打包与验收 | 安装包、WebView2、资源及许可证 | 干净 Windows 环境安装和运行通过 |

优先验证“macOS IPP 提交 PDF → Windows 指定打印机”的完整链路，再完善管理界面。

## 12. 测试与验收

### 自动化测试

覆盖：

- IPP 编解码、错误请求和不支持的操作。
- 设备鉴权、撤销及任务归属。
- PDF 内容与大小校验。
- 不同打印机路由隔离。
- 同一打印机串行执行。
- 重复请求及内容冲突。
- 打印命令参数。
- 排队任务取消。
- 服务重启恢复。
- 打印超时和不确定结果。
- 目标禁用或失效时不误投。
- 清理不影响等待及执行中的文件。

### 实机验收

至少使用两台 Windows 打印队列，优先覆盖不同品牌：

- Windows 客户端能配置并共享多台打印机。
- macOS 能分别添加、认证和选择目标。
- 中文 PDF、A4、份数打印正确。
- 在支持的设备上验证长边和短边双面。
- 不支持的能力不被错误展示或接受。
- 多打印机同时提交时不串机。
- 离线、失败、超时、退出和重启后不自动重复打印。
- 关闭窗口后托盘服务继续运行。
- 未单独安装 SumatraPDF 的 Windows 环境可在设置中下载组件后正常使用。
- 应用升级保留配置及任务数据。

真实打印测试需明确授权，并使用少量非敏感测试页。模拟测试通过不等于驱动或实际出纸验证通过。

## 13. 交付标准

1. Windows 客户端可共享多台已安装驱动的打印机。
2. macOS 通过 IPP 添加并选择目标打印机。
3. 无网页上传或通用文件上传入口。
4. 设置提供 SumatraPDF 手动下载、校验及状态展示，无需用户自行查找安装程序。
5. 任务持久化、路由明确，已识别的重试不重复提交。
6. 不确定结果进入待核查，不自动重打。
7. 提供实际可执行的安装、配置、测试说明及兼容性记录。

## 14. 评审补充建议

以下建议补齐实现与验收边界，不扩大首版功能范围。项目目录名称中的 macOS 指使用端，应用运行平台仍为 Windows。

### 14.1 开工前的兼容性验证

将第 11 节的完整链路验证作为正式开发的前置关卡，先用最小原型验证下列三项，再完善队列与界面：

1. macOS 实际发送 `Print-Job` 和 PDF，或通过可交付的 PPD 配置实现这一行为。
2. 系统打印界面能够输入和保存设备凭据，撤销后旧凭据无法继续提交。
3. 固定版本的 SumatraPDF 能向指定队列打印，并正确应用份数、A4 和两种双面方向。

记录 Windows/macOS 版本与架构、驱动版本、SumatraPDF 版本、添加方式及协议抓取结论；抓取材料须去除认证头和文档内容。若系统必须使用 Create-Job/Send-Document 或非 PDF 格式，应先记录为兼容性阻断项，重新确认范围，不直接扩展协议或格式支持。

建议首版先以 Windows 11 x64 为发布目标；具体最低 Windows 版本、macOS 版本和 ARM64 支持范围在此关卡定稿。开发机上可运行通用逻辑，不代表可发布 macOS 桥接服务。

### 14.2 设备令牌的认证协议

“设备令牌”是凭据形态，还需要选择系统打印客户端支持的认证协议。候选方案为 HTTP Basic：用户名使用非敏感设备标识，密码使用随机令牌；必须通过 14.1 的实机验证，不能假定 macOS 会发送自定义 Bearer 头。能力响应中的认证声明须与实际行为一致。

建议使用密码学安全随机源生成至少 256 位随机令牌，服务端保存校验哈希和非敏感标识。客户端提交的 `requesting-user-name` 只能作为展示信息，不能作为任务归属依据。认证必须先于大体积文档读取和 PDF 解析，失败请求不得入队。

撤销建议仅影响后续请求，包括正在接收但尚未持久化成功的请求；已接受任务保留，需由本地用户单独取消等待任务。提交事务前再次检查撤销状态。这样撤销访问与取消打印的含义明确。

如果采用 Basic 且不启用 TLS，令牌和文档均可能被同网段监听者获取；客户端配置页及安装说明应明确这一点。首版是否增加 IPPS 属于范围决策，不能以“令牌只存哈希”代替传输保护。

### 14.3 IPP 协议和打印语义

实施前固定支持的 IPP 版本、属性清单和错误码表。最小契约包括：操作列表、PDF 格式、A4 纸张、份数范围、单双面、默认值、打印机接收状态、稳定的 `job-id`/`job-uri` 和鉴权方式；只声明实现并验证过的能力。

HTTP 层需验证 `application/ipp`、分块传输、`Expect: 100-continue` 和连接中断行为；协议错误与 HTTP 认证错误分别处理。对属性长度、数量和嵌套深度设置限制。URI 中的打印机与任务归属必须一致，不得通过换路由查询他人的任务。[RFC 8010](https://www.rfc-editor.org/rfc/rfc8010.html)

`Validate-Job` 只验证请求属性和当前接收条件，不校验尚未传来的 PDF 内容，也不预留容量。`Print-Job` 必须重新检查。对影响打印效果但不支持的显式选项，保持拒绝策略；对普通元数据和未知可忽略属性，按协议规则处理，避免把所有额外属性都当成打印选项而拒绝客户端。

建议明确以下打印语义：A4 采用适应可打印区域的缩放，保持宽高比；非 A4 PDF 页面可缩放到 A4，其他目标纸张不开放。份数以最终规范化请求为准，并验证 macOS 没有提前复制页面造成份数相乘。页码范围由客户端生成对应 PDF，若仍携带服务端未支持的页码范围属性则拒绝。彩色设置不开放，但实际按驱动默认输出还是固定黑白须在原型阶段定稿，不能将“不提供彩色选项”理解为保证黑白。

显式传递规范化后的份数、纸张和单双面设置，防止 PDF 内嵌打印偏好改变结果。参数和退出码以锁定版本为准，不能直接套用在线最新版本文档。[SumatraPDF 命令行说明](https://www.sumatrapdfreader.org/docs/Command-line-arguments)

### 14.4 幂等识别的可实现边界

IPP 的 `request-id` 用于请求与响应关联，不是全局唯一的业务幂等键。不能仅凭“同设备、同打印机、同 request-id”认定重试，也不能仅凭内容摘要吞掉用户主动重复打印。[RFC 8011 第 4.1.1 节](https://www.rfc-editor.org/rfc/rfc8011.html#section-4.1.1)

先通过 macOS 实测确定是否存在可依赖的重试标识及其作用域，再决定识别窗口。若没有可证明的稳定标识，应明确第 8.3 节只能提供有限重复识别，无法保证响应丢失后的跨连接重试不重复打印；这属于交付风险，不得用摘要去重掩盖。

确认同一业务提交身份后，使用唯一约束和事务处理并发重试：同键同内容返回原任务，同键不同内容拒绝。摘要覆盖 PDF 字节和规范化后的全部有效选项。幂等记录与任务一起持久化，文档清理不应提前删除仍在识别窗口内的记录。

### 14.5 持久化与调度边界

返回成功前，PDF 必须完整持久化，任务和幂等记录必须提交。文件系统与 SQLite 不共享事务，应明确“临时文件、完成文件、任务记录”的写入顺序，并在恢复时处理孤立文件和缺失文件；缺失文件的等待任务不得执行。

领取任务时原子地将“等待”变更为“处理中”，先持久化执行意图再启动打印程序。取消使用同一状态条件更新，保证取消成功后不会启动打印。多个应用实例不能同时调度同一数据目录，建议每个数据目录仅允许一个实例。

同一 Windows 队列不能通过两个桥接 ID 绕过串行限制：建议拒绝重复绑定。队列重命名或重建后需重新确认绑定，即使名称相同也不能仅凭名称假定为原设备。能力配置改变不修改已接受任务的选项；执行前发现能力不再适用时停止该任务并说明原因。

### 14.6 生命周期与任务状态

建议将“停止服务”定义为停止接收及领取新任务，保留等待任务，等待当前打印调用结束；超出等待期限的调用记为待核查，不能认定未提交。禁用单台打印机同样停止接收和领取该打印机任务，重新启用后再恢复等待任务。

首版作为当前用户会话中的应用运行，不作为 Windows Service。关闭窗口继续托盘运行，主动退出或注销后无法接收任务；休眠时不可用。恢复后不得重新调用已进入处理中且结果不明的任务。登录启动应使用原配置，首次安装不在未选择打印机时自动开放共享。

建议采用以下映射，并在 macOS 上验证显示与重试行为：

| 内部状态 | IPP 状态建议 | 处理边界 |
|---|---|---|
| 等待 | pending；暂时禁止调度时 pending-held | 允许取消 |
| 处理中 | processing | 不接受执行前取消语义 |
| 已提交 | completed + queued-in-device，仅适用无法获取下游详细结果的网关模式 | 本地继续显示“已提交”，不声称已出纸 |
| 失败 | aborted | 仅在确认未提交时使用，不自动重试 |
| 待核查 | processing-stopped，附可读原因 | 禁止自动恢复或重打，保留材料待本地核查 |
| 已取消 | canceled | 保证未启动打印调用 |
| 模拟完成 | 仅模拟环境映射为 completed | 不向真实服务混入模拟记录 |

网关采用 `completed + queued-in-device` 的条件来自 [RFC 8011 第 5.3.7.1 节](https://www.rfc-editor.org/rfc/rfc8011.html#section-5.3.7.1)。macOS 仍可能将其显示为完成，安装说明必须解释其只代表转交；仅设置该原因值无法控制客户端文案。

待核查任务需要最小的本地处理闭环：允许记录人工核查结果并归档，保留原始不确定状态与审计记录，不伪造“确认出纸”，也不直接提供自动重打。未核查前不自动删除 PDF；相关磁盘占用达到上限时拒绝新任务并提示处理。

### 14.7 资源限制与清理建议值

以下为首版候选默认值，须经代表性 PDF 和两台打印机验证后锁定。限制应能由本地配置调整，但不必全部增加界面控件。

| 项目 | 候选默认值 | 超限行为 |
|---|---|---|
| 单个 PDF | 100 MiB，最多 500 页 | 拒绝，不入队 |
| 份数 | 1–99 | 与能力响应保持一致，超出拒绝 |
| 未完成任务 | 每设备 20 个、每打印机 100 个 | 拒绝新提交，返回可识别原因 |
| 文档存储配额 | 2 GiB，且保留至少 1 GiB 可用磁盘 | 预留上传占用，容量不足拒绝 |
| 同时上传 | 全局 4 个 | 其余请求明确返回繁忙 |
| 同时打印调用 | 全局 2 个，每 Windows 队列 1 个 | 其余持久化排队 |
| 上传超时 | 空闲 30 秒，总计 5 分钟 | 终止接收，清理临时文件 |
| PDF 校验超时 | 30 秒 | 拒绝，不启动打印 |
| 打印调用超时 | 5 分钟 | 待核查，不自动重试 |
| 已提交、失败、已取消的 PDF | 终态后保留 24 小时 | 超期清理，不影响任务记录 |
| 任务元数据与日志 | 30 天 | 仍在幂等窗口或待核查的记录除外 |

页数、字节数之外还应限制解析资源；用畸形和高复杂度 PDF 验证解析器不会长期占用服务。上述超时用于资源控制，不能据此推断打印是否发生。

### 14.8 安装与部署边界

安装说明应覆盖监听地址选择、端口冲突、Windows 防火墙私有网络规则、IP 地址变化后的重新配置，以及 WebView2 缺失时的处理方式。监听所有网卡不应成为未经提示的默认设置；不自动放行公共网络或配置路由器端口转发。

固定安装包架构和 SumatraPDF 版本、摘要及许可证材料，常规运行不依赖管理员权限。正式发布前确定签名方式及证书来源；升级前验证数据库迁移，失败不得覆盖原数据。卸载时明确保留还是删除用户数据，删除须由用户选择。

### 14.9 新增验收用例与决策记录

在第 12 节基础上增加：

- 原生 macOS 认证及重新认证、实际文档格式和操作序列验证。
- 合法主动重复打印不被误去重；并发同一重试仅生成一个任务；提交后响应丢失的行为有记录。
- 分块上传、慢速上传、认证失败、磁盘写满和配额并发竞争。

- 取消与调度竞争，停止与领取任务竞争，令牌撤销与提交竞争。
