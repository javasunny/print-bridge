# Windows 实机验证

本清单用于验证真实打印链路。当前开发环境为 macOS，交叉构建与模拟测试不能替代以下 Windows/macOS 联机验收。仅在用户授权后使用少量非敏感测试页。

## 交叉构建记录

2026-10-26 在 Apple Silicon macOS 使用 Rust 1.99.1、cargo-xwin 0.23.1、Tauri CLI 2.12.4 和 NSIS 3.13，成功构建 Windows x64 EXE 与 NSIS 安装包，输出到 `dist`。PE 格式和导入项已检查，应用无需额外分发 Python、SumatraPDF 或 VC++ Runtime DLL；WebView2 由安装程序按需处理。产物未签名，尚未在 Windows 上安装运行。

43 项 Rust 核心测试、3 项文档测试、4 项前端测试通过；另外显式运行的官方下载测试通过，验证了归档及 EXE 摘要、安装和重新打开后的离线就绪状态。静态检查通过。链接阶段的 LNK4099 提示涉及缺少 Microsoft CRT 调试符号，不影响生成 release 文件。

2026-10-26 macOS 兼容性修正后重新交叉构建了 Windows x64 EXE 和 NSIS 安装包。新版本允许匿名读取 IPP 能力，并响应 IPP 2.0 的现有操作。45 项 Rust 核心测试、3 项文档测试、1 项 macOS IPP 模拟探测和 4 项前端测试通过。本机模拟服务经 macOS `ipp2ppd` 探测可生成 PDF 过滤规则和 A4 纸张配置，`cupsfilter` 离线输出保持 PDF；真实添加、认证和出纸仍按下表验证。

Windows 服务更新后的联机只读查询确认 PDF/A4 能力正常，但 macOS 原生 Auto Select 仍选择 Generic PostScript。为此提供显式选择的 A4 单面 PPD，配置由在线服务能力生成；PPD 语法和离线 PDF 输出均通过测试。原生 Use → Other 添加、认证与出纸仍待验证。

0.1.1 增加可保存的设备认证开关，并兼容 macOS 原生队列附带的 A4 别名、PageSize、单页布局、不装订和文档元数据，以及 PDF/通用二进制格式标记组合。只接受不改变输出的默认值，文件仍须通过 PDF 校验。48 项 Rust 核心测试、3 项文档测试、2 项 macOS 离线测试和 4 项前端测试通过，桌面构建和 Windows x64 安装包交叉构建成功。另已显式运行本机临时 CUPS 队列测试，验证免认证 PDF 提交、入库和模拟完成；临时队列自动删除，未向真实打印机出纸。Windows 端更新后须继续验证真实打印。

原生队列测试需要本机打印机管理权限，单独执行：`cargo test --locked --test macos_ipp native_macos_queue -- --ignored`。常规测试不会创建系统打印机队列。

0.1.2 增加内存中的连接诊断记录，显示来源 IP、HTTP/IPP 状态及拒绝原因。51 项核心测试、3 项文档测试、2 项 macOS 离线测试和 5 项前端测试通过；原生队列模拟测试也确认已记录客户端 IP 和 Print-Job，Windows x64 安装包构建成功。Mac 只读探测确认现有 Windows 服务可达且认证模式为 none；这只能证明服务能响应查询，不能证明已提交打印任务。新的探测文件不要求无关的完整打印机属性，用于专门验证该桥接服务的 PDF 能力和连接。

0.1.3 根据实际应用打印附带的选项扩展原生 CUPS 队列测试，复现并修正 AP_ColorMatchingMode 等默认设置及 com.apple.print 私有票据被拒绝的问题。标准输出参数仍校验，非默认纸盒、彩色模型、双面等未支持值仍拒绝。请求体读取中断不再误报为超限，真实大小限制保持不变；诊断记录显示具体不支持的属性名。52 项核心测试、3 项文档测试、2 项 macOS 离线测试和 5 项前端测试通过，带应用选项的本机原生队列模拟测试通过，桌面构建及 Windows x64 安装包构建成功。真实 Windows 出纸仍待联机验证。

## 首次下载打印组件

安装应用后，打开“设置 → 下载打印组件”。应用检查官方稳定版并从 SumatraPDF 官方 HTTPS 域下载 x64 portable ZIP。3.6.1 核对锁定的 ZIP/EXE SHA-256；后续稳定版在 Windows 验证有效 Authenticode 签名、预期发布者及产品版本，再记录本地摘要。不会自动下载或自动执行打印。

下载失败时应显示错误并允许重试；未校验成功的组件不能标为就绪。验证首次下载、断网失败重试、校验失败，以及下载成功后重新打开应用仍可离线使用。组件位于用户应用数据目录的 `tools/sumatra`；原有下载不随应用升级清除。检查更新不安装文件；运行中的服务不能更新组件。更新失败应保留旧 EXE，更新后重启应用应能离线校验并使用。Windows 动态版本的实际签名验证需在新版上游发布时继续实测。

## 验收顺序

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 1 | 在未另装 SumatraPDF 的 Windows 11 x64 上安装应用 | 配置窗口启动，WebView2 缺失时安装流程可处理；设置中手动下载并校验组件后可启动打印服务 |
| 2 | 枚举并绑定两台 Windows 打印队列，分别使用稳定桥接 ID | 中文与含空格的队列名称正确，不能重复绑定同一队列 |
| 3 | 创建设备凭据，启动私有网络 IPP 监听 | 客户端给出正确 IPP 地址；无网页上传入口 |
| 4 | macOS 手动添加两台 IPP 打印机并认证 | 原生打印对话框可选；实际发送 PDF 与 Print-Job，凭据可以保存 |
| 5 | 向两个队列各提交一页测试 PDF | 路由正确；同一队列串行；不会改投系统默认打印机 |
| 6 | 测试 A4、两份、单面以及支持的双面方向 | 纸张、份数、方向正确；不支持的选项被拒绝 |
| 7 | 取消等待任务并同时提交其他任务 | 取消成功的任务没有启动打印调用 |
| 8 | 撤销设备凭据后重新提交及查询 | 原凭据被拒绝；其他设备不能查询或取消其任务 |
| 9 | 停止服务、关闭窗口、退出、重启 | 停止后不领取新任务，关闭窗口继续托盘运行；处理中断后为待核查，不自动重打 |
| 10 | 打印机离线、打印进程异常、调用超时 | 不将不确定结果认定为未提交，不自动重试 |

固定版本尚未完成实机验证前，进程成功退出只记录“已提交”；非零退出统一记录“待核查”。Windows 队列消失不证明实际出纸。
